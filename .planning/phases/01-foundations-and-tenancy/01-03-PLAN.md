# Phase 1 Plan 03: Auditoria imutavel e guardrails multi-tenant

## Objective
- **What:** Harden the foundation with append-only audit infrastructure, tenant-scoping primitives, and proof against cross-tenant access in API and worker paths.
- **Why:** The milestone explicitly treats audit and isolation as functional scope, not late hardening.
- **Output:** Shared tenant/audit primitives, tenant-scoped audit UI/API, worker guardrails, and automated cross-tenant tests.

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| API -> Audit store | Sensitive event metadata crosses from request handlers into durable logs. | Actor metadata, event type, summarized payload |
| API -> Worker | Tenant-aware async work crosses a queue boundary. | `tenant_id`, job identifiers, correlation IDs |
| Tenant-scoped UI -> Audit API | Authenticated users request filtered event history. | Date ranges, actor filters, event types |

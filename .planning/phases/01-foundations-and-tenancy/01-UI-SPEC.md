# Phase 1 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Surface Scope

| Surface | Goal | Required States |
|---------|------|-----------------|
| Signup and onboarding | Create the company account and owner user in one guided flow | default, inline validation, email confirmation pending, hard failure, success handoff |
| Login | Authenticate into the panel with generic error handling | default, loading, generic auth failure, session expired |
| Password reset request | Start reset flow without leaking account existence | default, submitted/generic success, expired link notice |
| Password reset completion | Let the user define a new password and invalidate old sessions | default, password rule failure, success confirmation, invalid token |
| Tenant basic settings | Edit business identity, timezone, WhatsApp number, and default due policy | default, dirty state, save success, save failure |
| Audit log list view | Inspect immutable security-relevant events scoped to the current company | populated, filtered, empty result, loading, backend failure |

## Inputs Applied

| Area | Source | Applied Decision |
|------|--------|------------------|
| Self-serve onboarding | `01-CONTEXT.md` D-01, D-04 | Signup must capture company name, primary email, WhatsApp phone, timezone, and default due policy |
| Tenant resolution | `01-CONTEXT.md` D-03 | No tenant switcher in login or in the app shell for Phase 1 |
| Session UX | `01-CONTEXT.md` D-05, D-07, D-08 | Server-side session, explicit logout, generic auth errors, session-expired re-entry flow |
| Reset UX | `01-CONTEXT.md` D-06 | Reset request and completion need dedicated confirmation states and no secret exposure |
| Audit coverage | `01-CONTEXT.md` D-09 to D-12 | Audit view must prioritize signup, login, logout, reset, settings changes, and authorization failures |
| Multi-tenant safety cues | `01-CONTEXT.md` D-13 to D-16 and `AGENTS.md` | UI must always feel single-company scoped, with no cross-tenant affordances or ambiguous labels |
| Brazilian UX | User objective and `REQUIREMENTS.md` AUTH-01 to AUTH-04 | All user-facing copy is Portuguese (Brazil), uses `empresa` instead of `tenant`, and defaults to `America/Sao_Paulo` |
| Visual baseline | default for greenfield repo | Warm neutral surfaces, dark ink text, teal/emerald accent, no purple-on-white default aesthetic |

## Visual Direction

- Tone: reliable, operational, contemporary Brazilian B2B.
- Use warm paper-like backgrounds instead of cold white canvases.
- Keep the product feeling serious and audit-friendly, not playful or startup-generic.
- Accent color is teal/emerald, not purple.
- Auth screens may use one supporting brand panel on desktop, but the app shell must stay compact and data-first.

## Language and Domain Terms

| Internal Concept | User-Facing Term |
|------------------|------------------|
| tenant | empresa |
| owner | responsavel da conta |
| audit log | trilha de auditoria |
| authorization failure | acesso negado |
| session expired | sua sessao expirou |
| default due policy | vencimento padrao |

Rules:
- Never expose `tenant`, `membership`, `payload`, or similar internal terms in the UI.
- Use direct second-person Portuguese (`voce`) and short operational verbs.
- Dates use `dd/mm/aaaa`; timestamps use `dd/mm/aaaa HH:mm`; currency uses `R$ 0,00`.

## Layout Contract

| Surface | Layout Contract |
|---------|-----------------|
| Signup and onboarding | Two-step flow inside a single `520px` form card. Step 1 captures responsible user email and password. Step 2 captures company data. On desktop (`>= 1200px`), show a left-side brand panel with one trust statement and three short operational bullets. On mobile, remove the side panel and keep the flow single-column. |
| Login | Compact auth card at `440px` width max. Brand mark and product name above the form. `Esqueci minha senha` stays inline under password. No tenant selector, no marketing carousel. |
| Password reset request | Same auth shell as login. Replace the form with a confirmation panel after submit. Confirmation copy must be identical whether the email exists or not. |
| Password reset completion | Same auth shell. Show password rules above the submit button, not as tooltip-only help. After success, show one confirmation card with CTA back to login. |
| Tenant basic settings | App shell with a simple top bar and content width capped at `960px`. Split settings into exactly two section cards: `Dados da empresa` and `Cobranca padrao`. Save actions stay in a sticky footer bar inside the content column once the form is dirty. |
| Audit log list view | App shell with header, filter bar, and dense table. Use a table from `768px` upward and stacked cards below that. Default sort is newest first. Default filter range is `Ultimos 7 dias`. Pagination is numbered, never infinite scroll. |

## Interaction Contract

| Rule | Contract |
|------|----------|
| Validation | Validate inline on blur and again on submit. Show the error below the field, never only in a toast. |
| Auth failures | Keep messages generic: invalid login, expired session, invalid reset link. Operational detail never appears in the UI. |
| Sensitive changes | Any change to company data or password shows a small note before submit: `Esta alteracao entra na trilha de auditoria.` |
| Session expiry | When the session expires, redirect to login and show one inline banner: `Sua sessao expirou. Entre novamente para continuar.` |
| Save feedback | Settings save uses inline success feedback in the sticky footer, not a detached toast only. |
| Audit payload summary | Show only stable summary text in the list. Never expose tokens, raw reset links, secret values, or full IP/user-agent strings. |
| Tenant scoping cue | After login, always show the current company name in the app header. This is the only tenant cue in Phase 1. |
| Mobile behavior | Auth flows must be fully usable at `360px`. Audit filters collapse into a bottom sheet on mobile. |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Criar conta da empresa |
| Login CTA | Entrar no painel |
| Reset request CTA | Enviar link de redefinicao |
| Reset completion CTA | Redefinir senha |
| Settings CTA | Salvar configuracoes |
| Empty state heading | Nenhum evento encontrado |
| Empty state body | Quando houver login, logout ou alteracao sensivel, os registros aparecem aqui. Ajuste os filtros ou realize uma acao na empresa atual. |
| Error state | Nao foi possivel concluir esta acao agora. Revise os dados e tente novamente. Se o problema continuar, tente mais tarde. |
| Destructive confirmation | Encerrar outras sessoes ativas: Isso vai desconectar acessos em aberto desta empresa. Continuar? |
| Sensitive change hint | Esta alteracao entra na trilha de auditoria. |

Copy rules:
- Prefer verbs first: `Criar conta`, `Salvar configuracoes`, `Redefinir senha`.
- Avoid legalese and backend jargon.
- Avoid optimistic filler such as `Tudo certo!`; use restrained confirmations.

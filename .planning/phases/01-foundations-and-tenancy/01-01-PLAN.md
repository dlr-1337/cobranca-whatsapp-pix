<threat_model>
## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Browser -> Web/API | Untrusted user input enters the platform through auth and onboarding forms. | Credentials, tenant profile input, cookies |
| API -> Postgres | Sensitive auth, tenant, and audit data crosses into durable storage. | Password hashes, session metadata, audit payloads |
| API/Worker -> Redis | Async job metadata crosses into a shared queue boundary. | `tenant_id`, job identifiers, replay metadata |

## STRIDE Register

| threat_id | category | component | disposition | mitigation_plan | files_to_check |
|-----------|----------|-----------|-------------|-----------------|----------------|
| T-01-01 | Spoofing | Runtime env loading | mitigate | Centralize env parsing with explicit required variables and fail-fast boot so apps cannot start with ambiguous secrets or hosts. | packages/config/**; apps/*/src/main.* |
| T-01-02 | Tampering | Local infrastructure bootstrap | mitigate | Use versioned compose/env files checked into the repo so developers do not improvise incompatible service settings. | docker-compose.yml; .env.example |
| T-01-03 | Elevation of Privilege | Shared data access package | mitigate | Reserve scoped repository interfaces now; do not expose generic unscoped helpers from `packages/db`. | packages/db/** |
</threat_model>
